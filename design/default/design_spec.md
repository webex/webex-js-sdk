# Contact Center SDK multi-region recovery design

## Overview

Design target: `@webex/contact-center`, `packages/@webex/contact-center`, in the current checkout. Unless a section explicitly gives another base, file paths are package-relative (`src/...`, `docs/...`); DAG `files` paths and command working directories start at the workspace root. Test Strategy suite paths are relative to the package `test/unit/spec/` directory; product acceptance uses full package unit runs. Root proposal documents are explicitly identified as workspace-root inputs. Authority is the complete 318-line root `requirement.md`, SHA-256 `a3b4d3ae7a0163e1fb145f4a8b36a6a2858490a1544e6fca99561239f57a4bb5`. The requirement records source baseline `d90e192166646e74dd39e95277607ac0b7e8d25a`; current-state statements below were checked against source, not inferred from that identifier. This is a proposed implementation, not a feature-test, independent-validation, or release-pass claim.

Preserve the valid decisions in root `implementation-plan.md` and `validation-and-evidence.md`: backend-only entitlement, independent live settings hydration, fresh admission, distinct ordinary/DR retry policies, two-stage interruption/cleanup, ordered station policy, conditional auto-Available, host-owned restart, and existing voice/Task/XState/RTD ownership. The requirement resolves target behavior where older proposal commentary differs. No prior `design/default/` deliverables existed.

An entitled switch synchronously fences old work and reconnects, then follows REQ-MR-012’s ordered policy after replacement Welcome. Automatic station restoration is attempted only for a prior backend-confirmed active station with `allowAutomatedRelogin` enabled and a usable snapshot. Earlier branches report `stationLoginRequired`: no prior station skips station wipe/reload/login; automation disabled skips automatic session requests; a missing usable snapshot reports `session-restore-failed` without those requests. Hosts receive complete `region:stateChange` snapshots distinguishing recovering, ready, manual station login, restart and unavailable. Registration still returns a complete Profile at its existing boundary; ready requires station success but promises neither Available nor uninterrupted audio. Ordinary network reconnection has no regional task wipe. No new SDK setting, Split/CDN gate, hostname hosting restriction, dependency, workspace or persistent store is introduced.

System boundary: a browser-oriented SDK/library and its documentation/tests. Host presentation/navigation, platform failover/entitlement provisioning, live operator execution, repository delivery operations and dependency/environment preparation belong to the flow/runtime and their existing owners. Dependency installation, including root `postinstall` (`patch-package && husky install`) and Husky’s `core.hooksPath` write to `.git/config`, is runner-owned preparation and never task acceptance or a prerequisite probe. This design adds no application route, visual harness or UI. Package-level tests cover the eleven SDK contract states and their associated actions.

Implementation uses Node 22.14.x, Yarn 3.4.1, package TypeScript 5.4.5, Babel/legacy tools, CommonJS declaration output, Jest 27, EventEmitter, WebexPlugin and XState 5.24.0. Keep existing exports, public method signatures, voice snapshots, task controls and backend event payloads compatible. The manifest’s modules remain Partial. MR-09 delivers diagnostics, host guidance and product integration tests; MR-10 depends only on that product node. MR-11 separately updates canonical documentation and manifest contract/module evidence after MR-09. The flow records fresh generator/validator runtime identity, working-tree source/spec SHA-256 fingerprints and authorized different-runtime semantic validation before the canonical stage completes. MR-09 has no manifest write scope. MR-11 preserves `validation.source_commit`, `validation.base_ref`, `validation.generator_*` and the entire `template_migration` object as historical baseline provenance, but marks the four current validator fields and changed-document headers pending before review. The flow-owned canonical validation stage records actual invocation identities and outcomes after review; Git-derived fields remain unchanged and are never current-content evidence. No task needs a commit, `rev-parse` result, Git reference or clean checkout; historical provenance does not identify current uncommitted content.

Product acceptance consists only of the package-scoped MR-01–MR-10 commands. MR-11 has separate documentation consistency and flow-owned canonical-validation checks. Root flow `prog-mini-js.config.json` commands `yarn run build` and `yarn run test` are not this design’s acceptance and are not required to pass for it; the root build also invokes installation and a monorepo build. Dependency installation/compilation remains runner-owned preparation.

## Cross-Cutting Concerns

**Concurrency and resources.** Registration, recovery, transport-attempt, station-session, Task operation and RTD epochs have distinct owners. Abort invalidates a lifetime; guards check both captured identity and epoch after every await, including catch/finally state mutations, so an old registration failure cannot clear a replacement wellness/session/profile state. Ordinary timer work is suspended during DR and the active attempt includes session restoration. State requests retain AQM's immediate duplicate admission; only one explicit waiter may await an already-dispatched DR automatic request, with no general state tail. Event handlers do not await UI callbacks. Complete cleanup owns resolve/reject/timers/listener references, the explicit wait reservation, workers/Blob URLs, Task actors/owned tracks and RTD request maps. Disposal is idempotent and does not remove host-owned resources. No retry loop or timer can restore a deliberately ended/replaced session.

**Configuration and persistence.** No new SDK config/feature flag, Profile field, browser-hosting requirement, schema, package, lockfile, module format or build change. Backend entitlement result, accepted history and station snapshots are memory scoped. Host sample uses only a timestamp in per-tab sessionStorage; no token/DN is stored. Null/undefined are runtime-checked despite non-strict TS configuration. Existing `disableWebRTCRegistration`, `allowAutomatedRelogin`, Webex App settings and authentication remain independently authoritative.

### Trust and security

REQ-006 authentication preservation reuses host Webex credentials/authenticated service resolution. Org/agent/session validation precedes changes. Admission alone supplies a trusted socket URL; the region label set is metadata only. No replacement URL is read from switch events, no region URL rewrite, no private U2C catalog mutation or per-retry forced catalog refresh. Logs/events never expose signed query data or saved station payloads. MR-03's T-003 `preservesHostAuthentication` and MR-06's T-007 `ordinaryReloginKeepsTasksAndAuth` verify the existing host auth boundary.
