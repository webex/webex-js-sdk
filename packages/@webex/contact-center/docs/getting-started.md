## Multi-region recovery

Listen for `REGION_RECOVERY_EVENTS.STATE_CHANGE` (`region:stateChange`) before registration.
Each frozen `RegionRecoveryState` is a complete snapshot. Replace the previous snapshot so omitted
placement, retry and automatic-action fields clear. The package exports the state and error catalogs
along with `RegionRecoveryState`, `RegionRecoveryStatus`, `RegionRecoveryReason`,
`RegionAutoAvailableStatus` and `RegionRecoveryErrorCode`.

| Status | Host behavior |
| --- | --- |
| `recovering` | Show recovery progress and keep commands disabled. |
| `ready` | The current socket and an initial or restored station session are accepted. Track `autoAvailable` and voice readiness separately. |
| `stationLoginRequired` | The SDK needs the app’s station sign-in flow. Use the existing `stationLogin()` with `BROWSER`, `EXTENSION` or `AGENT_DN`. Failed attempts stay in this state. |
| `reloadRequired` | Follow the [host restart guidance](#multi-region-recovery-host-restart). |
| `unavailable` | Show the terminal reason and follow the host's recovery flow. |

With `allowAutomatedRelogin` enabled, the SDK tries to restore the previous station. Apps can also
enable `config.cc.allowSavedStationLoginOnRecovery` to let the SDK try one saved DN or extension when it
needs a new station login and has no usable previous station details. The SDK uses saved choices
only when the agent opted into Desktop Enhanced Sign-in and the choices match the current profile.
Existing browser stations can recover automatically. Starting a new browser station still uses the
app’s sign-in flow for device permissions and any required prompts. Ask the agent for station details
when no eligible automatic sign-in succeeds.

A Welcome frame establishes transport. A successful station acknowledgment establishes readiness.
Active calls and audio can be interrupted by a switch. Retained Tasks have disabled controls and
reject with `STALE_TASK`. Obtain replacement Tasks through the existing Task events. Fresh
`FEATURE_ENABLEMENT` enables restored AI summary capabilities. Optional realtime services resume
independently, after manual login if required for the previous station.

Clear the host display when logout, deregistration or replacement begins and on primary multi-login.
Logout preserves registration and ordinary reconnect. Backend-confirmed logout clears the accepted
station. Logout without a usable primary rejects with `RECOVERY_INTERRUPTED`; retry after ordinary
reconnect. Attach essential listeners before registration and remove them at teardown.

## Multi-region recovery host restart

A region mismatch emits `reloadRequired`. A pending initial `register()` can also reject with
`REGION_RELOAD_REQUIRED`. The app owns the restart so it can reinitialize regional routing. A browser
app can do this automatically. This example shares one restart decision between the event and
rejection and uses the authenticated organization at decision time. It
persists the guard before navigation and allows one automatic restart per organization and tab
per 120 seconds. Missing storage, malformed timestamps and clock rollback block automatic restart.

<!-- region-recovery-host-example:start -->
```ts
function decideRegionRestart(
  getOrgId: () => string | null | undefined,
  now: number,
  getStorage: () => Pick<Storage, 'getItem' | 'setItem'>
): 'restart' | 'blocked' {
  try {
    const authenticatedOrg = getOrgId();
    if (typeof authenticatedOrg !== 'string' || !authenticatedOrg.trim() ||
        !Number.isFinite(now) || now < 0) return 'blocked';
    const orgId = authenticatedOrg.trim();
    const storage = getStorage();
    const key = `ccsdk:region-reload:${orgId}`;
    const previous = storage.getItem(key);
    if (previous !== null) {
      const last = JSON.parse(previous);
      if (typeof last !== 'number' || !Number.isFinite(last) || last < 0 ||
          last > now || now - last < 120000) return 'blocked';
    }
    storage.setItem(key, JSON.stringify(now));
    return 'restart';
  } catch {
    return 'blocked';
  }
}
```
<!-- region-recovery-host-example:end -->

Clear stale state after invoking register or logout so synchronous cancellation events cannot put
it back. Keep the restart guard across ordinary teardown. If the guard blocks automatic restart,
offer a manual restart after checking the live authenticated session and mismatch reason.

```ts
import {REGION_RECOVERY_EVENTS, REGION_RECOVERY_ERROR_CODES} from '@webex/contact-center';
import type {RegionRecoveryState} from '@webex/contact-center';

let region: RegionRecoveryState | undefined;
let registrationAttempt: {mismatchObserved: boolean} | undefined;
function requestHostRestart(): void {
  const decision = decideRegionRestart(
    () => webex.credentials.getOrgId(), Date.now(), () => window.sessionStorage
  );
  if (decision === 'restart') {
    window.location.reload();
  } else {
    console.error('Automatic restart blocked. Check the session and restart manually.');
  }
}
function onRegionState(snapshot: RegionRecoveryState): void {
  region = snapshot;
  if (snapshot.status === 'reloadRequired') {
    if (registrationAttempt) registrationAttempt.mismatchObserved = true;
    requestHostRestart();
  }
}
async function registerAgent() {
  webex.cc.off(REGION_RECOVERY_EVENTS.STATE_CHANGE, onRegionState);
  webex.cc.on(REGION_RECOVERY_EVENTS.STATE_CHANGE, onRegionState);
  const attempt = {mismatchObserved: false};
  registrationAttempt = attempt;
  try {
    const pending = webex.cc.register();
    region = undefined;
    return await pending;
  } catch (error) {
    const reason = (error as {data?: {reason?: unknown}} | null | undefined)?.data?.reason;
    if (reason === REGION_RECOVERY_ERROR_CODES.REGION_RELOAD_REQUIRED && !attempt.mismatchObserved)
      requestHostRestart();
    throw error;
  } finally {
    if (registrationAttempt === attempt) registrationAttempt = undefined;
  }
}
async function logoutAgent() {
  const pending = webex.cc.stationLogout({logoutReason: 'User requested logout'});
  region = undefined;
  return pending;
}
async function teardownAgent() {
  region = undefined;
  webex.cc.off(REGION_RECOVERY_EVENTS.STATE_CHANGE, onRegionState);
  await webex.cc.deregister();
}
```

## Multi-region recovery rollout and rollback

A compatible SDK release and backend entitlement are both required. During registration, the SDK
reads `organizationSetting.multiRegionEnabled` from the existing organization desktop-login
response. Literal `true` enables recovery and literal `false` disables it. Missing or invalid
values leave eligibility unknown and preserve ordinary registration. Register again to pick up
entitlement changes. Roll back through SDK release and backend entitlement management.
