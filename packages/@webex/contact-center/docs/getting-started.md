# Getting started

Onboarding for **@webex/contact-center**, a package inside the `webex-js-sdk` Yarn workspace. Run every
command from the workspace root. The package scripts run through `yarn workspace @webex/contact-center`
followed by the script name; `package.json` in `packages/@webex/contact-center` defines them.

## Prerequisites

| Tool or access | Version or requirement |
| -------------- | ---------------------- |
| Node.js        | 22.14 (workspace root `AGENTS.md`; the workspace `.nvmrc` selects `lts/jod`); `engines.node` in `package.json` is `>=20.x` |
| Yarn           | 3.4.1 (`packageManager` in the workspace root `package.json`) |
| Webex access   | N/A for building, unit tests, and linting. Running against Contact Center needs a Webex access token for a Contact Center agent |

## Install

Clone the workspace repository (https://github.com/webex/webex-js-sdk.git), change into its root
folder, and install the workspace:

```bash
yarn
```

The workspace `deploy.yml` and `pull-request.yml` workflows install with the same command.

## Build

```bash
yarn workspace @webex/contact-center build:src
```

`build:src` compiles `src/` (JavaScript and TypeScript) to `dist/` with source maps through
`webex-legacy-tools`, then runs the `build` script. `yarn workspace @webex/contact-center build` runs `build:src` for
`@webex/calling` and then `tsc` with declarations, writing `dist/types`, which the `types` entry
points at.

```bash
yarn workspace @webex/contact-center build
```

To build this package and its workspace dependencies in order:

```bash
yarn workspace @webex/contact-center compile
```

## Run

| Task | Command |
|---|---|
| Run locally | Consume through a Webex SDK host/application; this package has no standalone server. |

The workspace webpack build bundles `src/webex.js` into `umd/contact-center.min.js`, which the
Contact Center sample app in the workspace `docs/samples/contact-center` folder loads. The API
reference is generated by typedoc into the workspace `docs/wxcc` folder:

```bash
yarn workspace @webex/contact-center build:docs
```

## Tests

```bash
yarn workspace @webex/contact-center test:unit
```

```bash
yarn workspace @webex/contact-center test:style
```

`yarn workspace @webex/contact-center test` runs `test:style` and then `test:unit`:

```bash
yarn workspace @webex/contact-center test
```

To run one spec file, pass `--targets` with a path relative to `test/unit/spec`, as the workspace root
`AGENTS.md` describes (for example the path `cc.ts` for `test/unit/spec/cc.ts`). The unit specs import
`src/` directly; the sibling workspace packages they load resolve to those packages' `dist/`, so build
the workspace before trusting a result.

| Tier         | Command              | Test location | Framework   | External dependencies               |
| ------------ | -------------------- | ------------- | ----------- | ----------------------------------- |
| Unit         | `yarn workspace @webex/contact-center test:unit`     | `test/unit/spec` | jest (`webex-legacy-tools test --unit --runner jest`), jsdom | None |
| System / E2E | `yarn workspace @webex/contact-center test:e2e`      | Workspace `cc_playwright` folder | Playwright, workspace `playwright.config.ts` | The sample app on `https://localhost:8000` and Contact Center test credentials in `cc_playwright/.env` |

- Coverage or quality gate: 85% global lines, functions, branches, and statements, set by
  `coverageThreshold` in `jest.config.js` with `collectCoverage: true`
- Enforcement source: `yarn workspace @webex/contact-center test:unit` exits nonzero below the threshold; the pull-request workflow
  runs `test:style` and `test:unit` for changed packages and their dependents
- Test environment or QA dependencies: none for unit tests; the E2E tier is run from the workspace
  `e2e.yml` workflow

## Configuration and secrets

- Runtime credentials and service routing come from the host Webex SDK and its environment configuration. Never hardcode or log tokens.
- Required configuration: none to build or test. At runtime the host passes `config.cc`; the defaults
  are in `src/config.ts` (`allowMultiLogin`, `allowAutomatedRelogin`, `disableWebRTCRegistration`,
  `enableWxBetterTogether`, `clientType`, `isKeepAliveEnabled`, `force`, `metrics`)
- The package builds inside the Yarn workspace and consumes sibling `@webex/*` packages through workspace dependencies.
- Package or artifact access: publishing uses `yarn workspace @webex/contact-center deploy:npm` from the workspace release workflow
- Platform, simulator, device, or SDK setup: none; browser calling needs a browser with WebRTC
- Never commit credentials or copy production secrets into a local config.

## First-run verification

1. Run `yarn workspace @webex/contact-center build:src`.
2. Run `yarn workspace @webex/contact-center test:unit` and confirm Jest enforces the package's 85% global thresholds from `jest.config.js`.
3. Run `yarn workspace @webex/contact-center test:style`.

Expected result: all three commands exit zero and Jest prints no coverage threshold message.
