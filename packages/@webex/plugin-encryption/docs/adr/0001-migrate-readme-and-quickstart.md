# ADR-0001 - Migrate the README and quickstart into the specification, and retain both

## Context

Onboarding found two existing documents: `README.md`, the npm page, and `developer-quickstart.md`, a
walk-through of the hosted sample app. No other intent, design, or AI-authored spec exists in this
package. Both carry usage claims, so the source policy `migrate-existing` was chosen.

Checking their claims against `src/`, `package.json`, and the root `package.json` found these
differences, where code is the referee:

| Document claim | Code behavior | Evidence |
| -------------- | ------------- | -------- |
| `import Webex from '@webex/plugin-encryption'` then `Webex.init(...)` | True at runtime: `main` is `dist/webex.js`, which exports `Webex`. The published `types` entry declares the default export as `Cypher`, so TypeScript users see a different type | `package.json`, `src/webex.js`, `dist/types/index.d.ts` |
| README: sample call `webex.cypher.register()` after `ready` | Matches `src/cypher/index.ts` | `src/cypher/index.ts` |
| README: "Files in the `src/@webex/plugin-encryption` folder will be compiled, bundled, and served" | The source folder is `packages/@webex/plugin-encryption/src`; the quoted path does not exist | repository layout |
| README: KMS certificate validation is off by default and enabled with `config.encryption.shouldValidateKMSCertificate` | The default is `false` in the internal plugin; this package does not set it | `../internal-plugin-encryption/src/config.js` |
| README: CDN script `umd/encryption.min.js` | The file exists in the `webex` package | `packages/webex/umd/encryption.min.js` |
| Quickstart: `yarn build:local`, `yarn samples:build`, `yarn samples:serve` | All three scripts exist in the root `package.json` | `package.json` |
| Quickstart: options carry `useFileService`, `jwe`, `keyUri` | Matches `FileDownloadOptions` | `src/cypher/types.ts` |

## Decision

Account for the content of both documents in the canonical specification, and keep both files
unchanged. Record `spec_source_policy.mode` as `migrate-existing` with `migrated_source_disposition`
`retain`, and route both files in `spec_sources` as `source-material`, non-canonical.

Where each part of the sources now lives:

| Source unit | Canonical home |
| ----------- | -------------- |
| README Install (npm and CDN) | Module spec *Public surface* (`Webex` bundle row); `UC-003` |
| README Usage (links to developer portal and API reference) | Module spec *Evidence register* and this ADR; the API reference is generated by `build:docs` |
| README KMS certificate validation (`shouldValidateKMSCertificate`, `caroots`, `reportOnlyAssetsBaseUrl`, `carootsReportOnly`) | Module spec *Public surface* note and [architecture security](../architecture.md#security-architecture); the behavior itself belongs to the internal plugin |

| Quickstart prerequisites (token with KMS access) | [Getting started](../getting-started.md) *Prerequisites* and *Configuration and secrets*; `UC-003` |
| Quickstart authentication and initialization steps | [Getting started](../getting-started.md) *Run*; `UC-003` |
| README Development (`samples:serve`) | [Getting started](../getting-started.md) *Run* |
| README Maintainers, Contribute, License | Not migrated: repository-level facts owned by the workspace root |

## Why

Both documents are consumer-facing: the npm page and the sample-app guide. The developer chose to fold
their behavioral content into the specification while leaving the published pages in place, so neither
the npm page nor links to the quickstart break.

## Alternatives considered

| Alternative | Why it was not selected |
| ----------- | ----------------------- |
| `keep-separate` (do not fold content in) | Not selected by the developer |
| `reconcile` | Not selected by the developer |
| Delete both after migration | Rejected by the developer: `README.md` is the published npm page |

## Consequences

**Positive:**

- The module specification is the single behavioral reference; usage content is reachable from it.
- The npm page and the quickstart stay stable for consumers.

**Negative / tradeoffs:**

- Agents must not treat `README.md` as the method or error reference; code and the specification win.
- The stale source-folder path in the README stays until a maintainer edits it.

## Constraint on future changes

Do not delete `README.md` or `developer-quickstart.md` as part of spec maintenance. When usage text
changes, keep the module specification aligned with code first.
