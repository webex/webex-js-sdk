## Getting Started
With the Webex Calling SDK, you can effortlessly integrate fundamental audio calling capabilities into your solutions, enhancing the way your users connect.

- [Introduction to the Webex Web Calling SDK](https://github.com/webex/webex-js-sdk/wiki/Introducing-the-Webex-Web-Calling-SDK)
- [Quickstart guide](https://github.com/webex/webex-js-sdk/wiki/Quickstart-Guide-(Calling)).
 
## Developing

```bash
git clone https://github.com/\<your-fork\>/webex-js-sdk.git
cd web-js-sdk/
yarn install
```

## End-to-End Testing

The Playwright E2E suite in `playwright/` runs against live Webex backends using real
accounts, so the same account must never be active in two sessions at once.

Copy `playwright/.env.example` to `.env` at the repository root and fill in the account
credentials. Access tokens are generated by the OAuth setup project and written back into
`.env`; do not set them by hand.

```bash
# All projects
yarn workspace @webex/calling run test:e2e

# A single project (see playwright.config.ts for the full list)
yarn workspace @webex/calling run test:e2e --project="SET_REGISTRATION_1 - PROD"

# List without running
yarn workspace @webex/calling run test:e2e --list
```

`MOBIUS=http` (default) or `MOBIUS=ws` in `.env` selects the transport; a run covers
one transport only.

In CI the suite runs as the `Test - E2E Calling` jobs in `.github/workflows/pull-request.yml`:
PROD with `MOBIUS=http` and INT with `MOBIUS=ws`. They are gated on the `run_e2e` label, which
is removed again on every new push, so a label authorizes exactly one run against the commit
that was reviewed. Credentials come from the `CALLING_E2E_ENV` repository secret, which holds
the full contents of `.env`, minus the access tokens.

## Consuming SDK
To consume the latest stable version of the Calling SDK one can use NPM or CDN.
# NPM
```javascript
  npm install @webex/calling
```
(or)

```javascript
  yarn add @webex/calling
```

```javascript
  import Calling from '@webex/calling'
```
# CDN
```javascript
  <script src="../calling.min.js"></script>
```
